- **fix(sse):** a model id with a client namespace (`<namespace>/<combo>`) no longer throws `ReferenceError: getComboByName is not defined` during combo resolution. The settings/combo read-cache change (#17304) dropped the `getComboByName` import but missed the client-namespace lookup added in #16493, so every request whose model was neither a combo nor a catalog id with a `/` crashed the combo check (reasoning routing included). The lookup now goes through `getCachedComboByName`, like the other two exact-name lookups in `getCombo()`.
